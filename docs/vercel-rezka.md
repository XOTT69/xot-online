# Rezka на Vercel Hobby

Статус 28.10.2026: функція розгорнута у `https://xot-rezka.vercel.app`.
Картки, озвучення й серії доступні, але відео повертає `url: false` і в iad1,
і в fra1. Гостьову сесію виправлено; відтворення через Vercel не підтверджене.
[Повний звіт](rezka-vercel-2026-10-28.md). Production 0.3.15 працює за старою адресою.

## Що розгортається

- Одна Node-функція `POST /api/rezka`, той самий парсер і перевірка картки,
  що використовуються у Worker. Потрібен приватний `XOT_SERVER_TOKEN` від
  32 символів. Ключ не передається Rezka.
- `GET /api/rezka` повертає лише стан конфігурації. Це не перевірка джерела.
- Темна сторінка перевірки у корені: фільм «Топ Ґан: Меверік» і серіал
  «Король Талси», озвучення, список серій та реальні відповіді API потоків.
  Ключ вводиться локально, не записується у сховище браузера; звіт не містить
  ключа чи відеоадрес. Отримання посилання не оголошується відтворенням.
- Відео не проксіюється, немає БД, фонових cron або тримання ноутбука
  увімкненим. Функція має ліміт 45 секунд; окремі запити Rezka — 8 секунд.

Хостинг обрано як кандидат після відмови від оренди й домашнього сервера.
Це перенесення адаптера, а не обіцянка усунути антибот-обмеження.

## Запуск

1. Увійти у Vercel через GitHub, обрати особистий **Hobby**, не Pro trial.
   [Hobby](https://vercel.com/docs/plans/hobby) призначений для особистого
   некомерційного використання; ліміти застосовуються і до API.
2. Відкрити [Deploy на Vercel](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2FXOTT69%2Fxot-online%2Ftree%2F0e3e4260ad572bf1e164157ae12dac2ca7908ef2&project-name=xot-rezka&repository-name=xot-rezka&env=XOT_SERVER_TOKEN&envDescription=Private%20adapter%20key%3A%20use%20a%20random%20value%20of%20at%20least%2032%20characters&envLink=https%3A%2F%2Fgithub.com%2FXOTT69%2Fxot-online%2Fblob%2Fcodex%2Fdirect-balancer-launch%2Fdocs%2Fvercel-rezka.md).
   Посилання зафіксовано на перевіреному коміті `0e3e426`, щоб Vercel не
   розбирав `codex/direct-balancer-launch` як гілку `codex` і папку
   `direct-balancer-launch`. Сторінку нового посилання перевірено до входу;
   створення проєкту в акаунті цим не підтверджується.
   Vercel створює копію репозиторію у вашому GitHub. Інший шлях — імпортувати
   поточний репозиторій і вручну вибрати гілку `codex/direct-balancer-launch`.
   Root Directory — корінь, Framework — Other; `vercel.json` містить команди
   встановлення, функцію та окрему статичну папку. Звичайний `public/m.js`
   на цей кандидат не переноситься.
3. Задати `XOT_SERVER_TOKEN`: новий випадковий ключ від 32 символів. Можна
   створити у менеджері паролів або командою `openssl rand -hex 32`. Зберегти
   його у менеджері паролів. Не передавати в чат чи URL. Якщо ключ змінено
   після першого запуску, виконати Redeploy.
4. Відкрити отриману production-адресу `https://…vercel.app`, ввести той самий
   ключ і натиснути **Перевірити**. Один запуск перевіряє два тайтли, без
   циклічного опитування. Можна скасувати очікування.
5. Натиснути **Скопіювати звіт** і передати звіт або публічну адресу проєкту.
   Публічна адреса дозволяє перевірити health, але для перевірки джерела
   потрібен запуск діагностики з приватним ключем у вашому браузері.

Production-адреса має бути доступна для серверних запитів без входу у
Vercel; Preview може вимагати Vercel Authentication. Приватний ключ адаптера
все одно потрібен для POST. Обмеження не вимикаються автоматично.

## Після перевірки

Якщо обидва тайтли повертають потоки, наступний етап — підключення лише
Rezka до функції та реальне відео у Lampa/VIDAA: початок, перемотування,
перехід між серіями й скасування. Filmix та інші адаптери залишаються на
поточному Worker. Не виставляти наявний загальний `XOT_BACKEND_URL`: він
перенаправляє також Filmix, а Vercel-кандидат його не обслуговує.

До цих перевірок ні новий клієнт, ні серверні секрети production Worker не
змінюються. Якщо Rezka повертає обмеження доступу, це зберігається як помилка
джерела; успішний пошук або зелений health не означає робочого відтворення.

Первинна документація: [Node і Web Standard handlers](https://vercel.com/docs/functions/runtimes/node-js),
[vercel.json](https://vercel.com/docs/project-configuration/vercel-json),
[Deploy button](https://vercel.com/docs/deploy-button).

## Виконані локальні перевірки

179 тестів пройшли, зокрема авторизація до звернення до джерела, збереження
озвучення/серії, передавання реальної відмови джерела, відсутність ключа у
запитах Rezka, звіт без приватних URL, відмова для іншої картки та скасування.
Функція зібрана локально з залежностями; зібраний entrypoint відповідає на
health. Це локальна збірка, не результат Vercel deployment.

У справжньому Chromium з контрольованими відповідями перевірено фільм і
серію, clipboard-звіт, політику CSP, ширину 360 px, відмову джерела й
відсутність пізнього результату після скасування. Ці відповіді не є доказом
доступу до Rezka із мережі Vercel або реального відтворення відео.
