# HDRezka: перевірка 28.10.2026

Статус: робоче відтворення з Cloudflare Worker не підтверджене. Поточний
опублікований плагін залишається 0.3.15; виправлення адаптера у 0.3.16
підготовлені в draft PR. Не слід описувати їх як усунення серверного обмеження.

Цільові пристрої користувача — Hisense VIDAA та звичайний браузер на ноутбуці.
Домашній адаптер із постійно увімкненим ноутбуком користувач відхилив. Нових
домашніх сервісів, тунелів, системних програм чи платного сервера не налаштовано.

Локальна перевірка у справжній Lampa/Chromium підтвердила українське відео
«Меверіка», перемотування, серії «Короля Талси» 1×1 → 1×2 і скасування пізнього
запуску. Вона використовувала тимчасовий локальний тестовий транспорт і не є
перевіркою відтворення через опублікований Worker або фізичний телевізор VIDAA.
Цей тестовий транспорт не включено до плагіна.

Якість у відповіді Rezka та фактичні кадри можуть відрізнятися, зокрема на
початкових сегментах. Під час тесту API повертав позначки 360p/480p/720p/1080p,
але в конкретні моменти декодер показував 854×480 або 1920×1080. Позначки API
не видаються за незалежну перевірку роздільності всього відео; 2160p не вигадується.

## Виправлення коду

- Додано оригінальну назву, рік і перевірку ID сторінки; назви зіставляються
  точно, а не за фрагментом чи лише роком.
- Якщо у пошуковій картці немає оригінальної назви, перевіряються метадані
  максимум трьох відповідних кандидатів. Помилка доступу не стає успішним
  порожнім результатом.
- Вкладені елементи одного перекладача не створюють дубльованих озвучень.
- Для фільмів доступне «Усі озвучення». Вибір озвучення змінює список без
  автоматичного запуску відео; явний вибір зберігається.
- Ідентичність картки повторно перевіряється перед поверненням озвучень.
- Порожня відповідь відео та вимога входу/доступу повертають зрозумілі помилки,
  а не успішний список потоків.
- Використовується канонічний домен `rezka.ag`; власна адреса сервера, як і
  раніше, задається лише конфігурацією розгортання, не запитом клієнта.

Ці виправлення корисні для дозволеного мережевого доступу, проте не усувають
відповіді 403 від джерела для Worker. CAPTCHA, авторизація, TLS-відбитки,
регіони або IP не підмінялися.

## Чому Android-рішення не підходить цим пристроям

У поточному вихідному коді Lampa `Reguest.native` використовує окремий HTTP
Android лише на Android. На інших платформах він повертається до звичайного
браузерного запиту з CORS. Це узгоджується з
[поясненням автора Lampa](https://github.com/yumata/lampa-source/issues/225).
Наявність цього методу в JavaScript не доводить доступності нативного HTTP
на VIDAA чи у звичайній вкладці браузера.

Первинні референси протоколу:

- <https://github.com/SuperZombi/HdRezkaApi>
- <https://github.com/ndenissov/HDRezka>

За поточних обмежень не знайдено підтвердженого шляху повністю автономної
інтеграції Rezka для цих пристроїв лише через цей Worker. Для такого варіанта
потрібен сумісний серверний доступ, який приймає саме джерело; будь-який
довільний VPS також не гарантує його.
