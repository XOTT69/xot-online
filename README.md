# ХОТ — власні балансери для Lampa

Версія 0.3.8 відкриває **власний** компонент `xot_online`: картка ліворуч, пошук і перемикач **Балансер** зверху, озвучення/серії справа. Плагін не завантажує Online MOD або Lumio. Filmix, Eneyida, KinoVezha, UASerials, HDRezka й AniLibria мають окремі адаптери в цьому репозиторії.

## Поточний режим — без оренди

У версії 0.3.8 UAKino/Ashdi вилучено з балансерів, загального й резервного пошуку, реєстру додаткових API та Worker-адаптерів. Старий збережений вибір UAKino відкриває Filmix. Причини попередньої перевірки залишені лише в [архіві дослідження джерел](docs/source-candidates.md).

За рішенням користувача працюємо на наявному Cloudflare Worker, без VPS і додаткових платних сервісів. Відео відтворюється безпосередньо з HTTPS CDN джерел; Worker обробляє пошук і метадані. Підключення `XOT_BACKEND_URL` не налаштоване. Серверний набір у `server/` збережений як необов’язковий варіант на майбутнє.

[Безкоштовний тариф Workers](https://developers.cloudflare.com/workers/platform/limits/) має ліміти 100 000 запитів на день і 10 мс CPU на запит. Поточна реалізація не вимагає платних KV, R2, Containers або VPS.

## Встановлення

```text
https://xot-online.ai-beta69690.workers.dev/m.js
```

Після оновлення перезапустіть Lampa. Кнопка **ХОТ** одразу відкриває результати Filmix або останнього обраного власного балансера. Вона має власний SVG-значок і розміщується поруч із кнопками перегляду перед закладками та іншими службовими діями. Через **Балансер** можна змінити джерело, через окрему кнопку **Озвучення** поруч із ним — вибрати студію або повернути всі озвучення. Вибір запам’ятовується окремо для картки й балансера. Через **Фільтр** можна вибрати сезон, повторити пошук і керувати Filmix-акаунтом. Вибір рядка відео запускає вбудований плеєр Lampa; доступні якості передаються його перемикачу. Позиція перегляду зберігається через Lampa.Timeline.

## Перевірений стан

### Усі джерела, мова, якість і наступна серія

- **Балансер → Усі джерела** шукає поточну картку одразу в доступних адаптерах. Результати з’являються поступово з назвою джерела, озвученням та якостями. Помилка або таймаут одного джерела не прибирає вже знайдені потоки інших. Збіги звіряються з назвою, роком і типом картки. У списку залишаються знайдені відео та підтверджені озвучення. Порожні, неоднозначні й недоступні джерела та службові статуси приховані. Недоступні озвучення також не додають зайвих пунктів до загального вибору озвучень і сезонів. До перших результатів видно загальний індикатор пошуку; якщо нічого не знайдено, залишається одне повідомлення з кнопкою повторного пошуку. Через верхній перемикач можна відкрити будь-який окремий балансер і побачити причину його помилки або недоступності озвучення.
- **Українська автоматично** ввімкнена за замовчуванням: обираються доступні озвучення з явною українською мовною позначкою. Назва студії сама по собі не визначає мову. Ручний вибір конкретного озвучення або «Усі озвучення» має пріоритет і запам’ятовується. Пункт **Озвучення → Автовибір української** повертає автоматичний режим; у **Фільтрі** його можна вимкнути. У режимі всіх джерел показуються українські варіанти з різних балансерів.
- **Фільтр → Бажана якість** зберігає стандартне налаштування Lampa `video_quality_default`. Ручна зміна якості у вбудованому плеєрі ХОТ також його оновлює. Якщо бажаної якості немає, обирається доступна нижча (або найменша доступна, якщо нижчих немає), а бажане значення зберігається для наступного відео. Доступність 2160p та ліміти акаунта визначає джерело.
- **Наступна серія** та список серій працюють у вбудованому плеєрі Lampa. Черга впорядкована за сезоном і номером серії, зберігає те саме джерело й озвучення та може переходити між сезонами. Інші студії не підставляються автоматично. Плейліст конкретної серії отримується лише при її виборі. Автоперехід після завершення використовує стандартне налаштування Lampa `playlist_next`. Зовнішні плеєри можуть не підтримувати таку динамічну чергу.

Усі чотири функції перевірено у справжній Lampa/Chromium. Перевірка включає повільне джерело, окрему помилку, чужий фільм того самого року, ручний вибір мови, збереження бажаних 2160p при фактичному потоці 480p, зміну на 720p і реальне відтворення наступної серії. Запізніла відповідь не відкриває вже закритий плеєр.

### Резерв при помилці плеєра

Якщо вбудований плеєр повідомляє про фатальну помилку або не готовий до відтворення протягом 15 секунд, ХОТ шукає **резервне джерело** для тієї самої підтвердженої картки. Для серіалу потрібен точний збіг сезону й номера серії. Меню показує джерело, озвучення та доступні якості; перемикання відбувається після вибору користувача. Новий плеєр відновлює час і будує чергу наступних серій обраного озвучення. Це позиція за часом; різні монтажні версії можуть мати часові розбіжності.

Хостинг, на якому виникла помилка, та його відомі спільні дзеркала виключаються з резерву. Пошук має загальний таймаут 20 секунд; помилка окремого джерела не скасовує решту. Якщо нічого немає, доступний повторний пошук. Закриття плеєра скасовує запити й запізнілі меню. Ручний непідтверджений збіг іншого фільму не запускає резервний пошук за початковою карткою. Автоматичне меню стосується вбудованого плеєра Lampa, який передає події помилок і готовності.

У Lampa/Chromium перевірено перехід із Eneyida на українське DniproFilm у Filmix для **Короля Талси, сезон 2, серія 1, з 65-ї секунди**, а потім відтворення серії 2 у новій черзі. Якість резерву визначає джерело: анонімний Filmix у цьому тесті повернув 480p/360p. Інші фільми та спільні несправні дзеркала не пропонувалися.

### Балансери

| Джерело | Реальна перевірка |
| --- | --- |
| Filmix | Власний Worker виконує пошук і повертає потоки. Українське озвучення «Оселя зла: Вітаємо у Раккун-Сіті» відтворено у справжній Lampa/Chromium без стороннього онлайн-плагіна. Анонімно доступні 480p. |
| Eneyida | Власний Worker знаходить фільм, читає публічний PlayerJS-плейліст і повертає справжні HLS-якості. На тестовому Worker у Lampa/Chromium відтворено «Оселю зла» у 720p та 1080p, а також серію другого сезону «Короля Талси». Без акаунта й оренди сервера. |
| KinoVezha | Власний пошук каталогу. У Lampa/Chromium відтворено фільм у 720p/1080p та першу серію другого сезону «Пуститися берега». Публічне дзеркало перевіряє назву й рік медіафайлу. |
| UASerials | Власний пошук і читання конфігурації вкладок плеєра. У Lampa/Chromium відтворено фільм у 720p/1080p та першу серію другого сезону «Короля Талси». |
| HDRezka | Власний пошук із Worker знаходить фільм. Сторінка плеєра в поточній перевірці повертає «Проверяем, что вы не бот!». Це показується як обмеження доступу, а не як відсутність фільму. Реальне відтворення Rezka з Worker поки не підтверджено. |
| AniLibria · аніме | Прямий офіційний API пошуку та HTTPS HLS-потоки, без ключа й стороннього плагіна. Прапорці обмежень релізу враховуються. |
| Власні JSON API | Підключаються окремо; неввімкнені джерела не показуються як робочі. |

Filmix API зараз має некоректний HTTPS-сертифікат. Тому **лише анонімні** пошук/читання відео можуть перейти на його публічний HTTP endpoint. Для кожного такого запиту створюється новий неприв’язаний device ID. Особисті токени, прив’язка пристрою й профіль працюють **тільки через HTTPS**, без послаблення перевірки сертифіката. Клієнт звертається до Worker по HTTPS, а у плеєр допускаються тільки HTTPS URL. Доступна якість визначається відповіддю Filmix та станом акаунта. Повний перелік озвучень зберігається окремо від придатних потоків: якщо для озвучення є лише якість вище поточного ліміту, воно залишається в списку з поясненням і не видається за доступне для відтворення. Для серіалів більше немає обрізання плоского списку після 350 рядків.

Автоматичний пошук звіряє повну назву, рік і тип контенту з відкритою карткою. Інший фільм того самого року або продовження зі схожою назвою не потрапляє в список. Підтверджена локалізована назва Filmix допомагає шукати ту саму картку в Rezka. Для ручного пошуку через поле вгорі можна переглядати ширші результати.

HDRezka отримується через HTML-парсер і публічні AJAX дії `get_movie`, `get_episodes`, `get_stream`. Перенаправлення дозволені лише на відомі HTTPS-адреси сервісу. CAPTCHA та обмеження доступу не обходяться.

Eneyida використовує пошук самого сайту й публічні плеєри HDVB UA/Tortuga. Трейлери не потрапляють у список потоків, скрипти сторінок не виконуються. Якості визначаються HLS-плейлістом, тому 2160p показується лише за наявності відповідного варіанта. Для перевіреної «Оселі зла» доступні 480p/720p/1080p. Серіали зберігають сезони та озвучення; відеоплейліст запитується при виборі конкретної серії. Якщо HLS має окремі аудіодоріжки, зберігається майстер-плейліст із режимом «Авто», щоб не втратити звук. Worker не проксіює відеобайти. [Перевірка інших кандидатів](docs/source-candidates.md).

KinoVezha й UASerials мають власні каталоги, але частково використовують спільний з Eneyida відеоархів. Їхній основний Tortuga-плеєр із Cloudflare зараз повертає HTML 404 зі статусом 200. Для відомих публічних адрес `vod/vid` та `embed/embd` адаптер може перевірити HDVB UA: крім ідентифікатора, повна оригінальна назва та рік фільму мають збігатися з читабельним ім’ям HLS-медіафайлу. Для серіалів звіряється назва. Непідтверджені й непрозорі адреси дзеркала не повертаються. Це додаткові каталоги, а не гарантія незалежного резервного відеохостингу.


## Додаткові джерела з прикладу Lumio

[Розбір наданого прикладу](docs/source-audit.md). Lumio використовує власний сервер Lampac/Mitsu і його протоколи доступу. Наявність назви в його меню не означає наявності незалежного робочого адаптера в ХОТ. Код Lumio й його VIP-токени не імпортуються в плагін.

## Worker або власний VPS

За замовчуванням усе виконується на Cloudflare Worker. Для запуску **тих самих власних адаптерів** на звичайному Linux-сервері підготовлено Node backend, Docker Compose, Caddy/HTTPS і приватний канал Worker → backend. Адреса плагіна при цьому залишається та сама. [Розгортання VPS](server/README.md).

Для підключення сервера у Worker задаються:

- `XOT_BACKEND_URL` — HTTPS origin вашого API, наприклад `https://api.example.com`.
- `XOT_BACKEND_TOKEN` — секрет Worker, який збігається з `XOT_SERVER_TOKEN` на сервері.

Це переносить виконання адаптерів; саме по собі не додає Lampac, акаунти сервісів або гарантію доступу до Rezka. Після запуску на VPS кожен сервіс перевіряється окремо.

## API

- `GET /api/health` — Worker, список `native_balancers` і кількість налаштованих JSON API.
- `POST /api/filmix` — `probe`, `pair`, `confirm`, `search`, `post`, `profile`.
- `POST /api/anilibria` — `search`, `post` через офіційний AniLiberty API.
- `POST /api/eneyida` — `search`, `post`, `stream`; якості фільму визначаються одразу, серії — при виборі.
- `POST /api/kinovezha`, `POST /api/uaserials` — `search`, `post`, `stream` через власні адаптери каталогів.
- `POST /api/rezka` — `probe`, `search`, `post`, `episodes`, `stream`.
- `GET /api/providers` — додаткові JSON API та стан їхньої конфігурації.
- `GET /api/search?title=Example&year=2026&provider=catalog` — пошук у налаштованих каталогах.

У `/api/health` поле `provider_count` рахує тільки додаткові налаштовані API. `native_balancers: ["filmix", "eneyida", "kinovezha", "uaserials", "rezka", "anilibria"]` — реалізовані адаптери, а не обіцянка доступності сторонніх сервісів.

Підтримуються змінні `XOT_CATALOG_URL`, `XOT_UASERIALS_API_URL`, `XOT_UAFILM_API_URL`, `XOT_FILMIX_API_URL`, `XOT_REZKA_API_URL`. Кожна має вказувати на власний/дозволений HTTPS JSON API, а не головну сторінку сайту. Формат відповіді:

```json
{"results":[{"title":"Example","year":2026,"url":"https://media.example/video.m3u8","quality":"1080p","translation":"Українська"}]}
```

`KODIK_TOKEN` вмикає тільки серверний пошук метаданих Kodik; цей адаптер не заявляється як власне джерело потоків.

## Розробка й перевірка

```bash
npm ci
npm test
npm run dev
npm run deploy
```

Канонічні файли — `public/m.js` та `public/online.js`. Після редагування виконайте `npm run sync`; тести й деплой перевіряють однаковість копій у корені. Деплой зберігає наявні змінні Worker. CI перевіряє синтаксис, адаптери, приватний backend, маршрути та збірку Wrangler.

Для живої браузерної перевірки потрібен Chromium, встановлений для `playwright-core`, або змінна `PLAYWRIGHT_EXECUTABLE_PATH` з його шляхом:

```bash
npm run smoke
# Тестова публікація:
XOT_TEST_ORIGIN=https://your-preview.workers.dev npm run smoke
# Eneyida: реальне відтворення 720p/1080p та вибір сезону/серії
npm run smoke:eneyida
npm run smoke:kinovezha
npm run smoke:uaserials
npm run smoke:features
npm run smoke:backup
XOT_BACKUP_AGGREGATE=1 npm run smoke:backup
# Нові локальні скрипти проти реальних API до публікації:
XOT_LOCAL_ASSETS=1 npm run smoke:features
```

Ця ручна перевірка відкриває справжню Lampa, передає подію картки фільму, завантажує публічний `m.js`, перевіряє Filmix-відтворення та верхнє меню HDRezka. Окремо перевіряються видимість значка до наведення, позиція кнопки між плагіном перегляду та закладками, вибір українського озвучення через кнопку зверху й відновлення цього вибору після повторного відкриття картки. У звіті Rezka може мати `restricted`; це не успішна перевірка її відтворення. Зовнішня мережа, сервіси та конкретні телевізори перевіряються окремо від детермінованих тестів.

Спільний сценарій `scripts/smoke-public-players.mjs` для Eneyida, KinoVezha й UASerials відкриває джерело через справжнє меню **Балансер**, перевіряє фактичну ширину кадру 1280/1920 та тривалість фільму понад 6000 секунд. Потім відкриває серіал, обирає другий сезон через **Фільтр** і перевіряє, що запитується відео лише однієї обраної серії.

`smoke:backup` інжектує фатальну подію у справжній плеєр, обирає реальний потік іншого CDN, звіряє сезон/серію/час, наступну серію, резерв із режиму «Усі джерела», завислий запуск (меню через приблизно 16 секунд), скасування запізнілого резерву та закриття його меню разом із плеєром.

Сценарій `smoke:features` також перевіряє приховування порожніх і недоступних джерел у загальному списку, недоступного озвучення та його сезону у фільтрах, спільне повідомлення за відсутності результатів і збереження пояснень при відкритті окремого балансера. Версія 0.3.8 перевіряє відновлення після старого вибору UAKino, його відсутність у перемикачі та відсутність запитів до вилученого джерела.
